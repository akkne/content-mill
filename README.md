# Content Mill

Content Mill — платформа для подготовки, планирования, публикации и анализа короткого контента. В FastAPI и Next.js работают вход, проекты, структурированный контекст клиента и дерево папок базы знаний. Остальные продуктовые возможности описаны в [функциональной спецификации](docs/features-description.md) и развиваются поэтапно. [Автономные HTML-демо](frontend-mvp/README.md) работают отдельно.

## Быстрый запуск

Нужны Docker и Docker Compose. Скопируйте `.env.example` в `.env` для настройки портов (можно запускать и без копирования, тогда используются 8000 и 3000):

```bash
cp .env.example .env
docker compose up --build
```

Откройте интерфейс на <http://localhost:3000>, проверку API на <http://localhost:8000/health> или документацию FastAPI на <http://localhost:8000/docs>. Compose запускает PostgreSQL, локальный S3-эмулятор и оба приложения с автообновлением кода. Откройте «База знаний», выберите проект и папку. Кнопка «Добавить примеры материалов» создаёт отдельное дерево с документами и исходными PNG и MP4 из HTML-демо. Дважды нажмите файл для просмотра или воспроизведения.

При создании проекта в базе знаний появляется дерево папок. Корень отображает введённое имя проекта. В «Бренд» входят «Товары», «Формат» и «Правила бренда». В «Промптах» новый проект получает десять редактируемых документов для подготовки короткого ролика. Список и основания выбора — в [решении о стартовых промптах](docs/decisions/0007-starter-prompts.md) и [дополнении об образах персонажей](docs/decisions/0008-character-handoff.md). В «Ролики/CM-000123» подготовлены папки документов и материалов.

В разделе «Личные библиотеки» под деревом базы знаний доступны две карточки. В «Аватарах» создайте персонажа, перетащите фотографии в папки лица и полного роста, добавьте одежду и документ с разрешением. Откройте папку персонажа, назначьте голос и добавьте аватар в нужные проекты. Для работы с голосами выберите «Голоса». В личной библиотеке можно создать голос по ID или выбрать его из каталога ElevenLabs с поиском, фильтрами и прослушиванием. При открытии каталога переключатель RU/EN определяет язык голосов. Язык можно уточнить вручную в фильтре каталога. В списке «Мои голоса» нажмите «Добавить в проект», отметьте нужные проекты и сохраните изменения. В проекте кнопка «+ Голос» открывает таблицу личных голосов. Чтобы включить каталог и озвучку, задайте серверный ключ Lumean `LUMEAN_API_KEY` в локальном `.env` и выполните `docker compose up -d backend`. Для каталога нужно право `voices.read`. Для кнопки «Озвучить текст» нужны также `templates.write`, `orders.write`, `orders.read`, `orders.download` и доступ к ElevenLabs. Модель — `eleven_multilingual_v2`. Готовую дорожку можно прослушать и сохранить из плеера. Ручной ввод работает без ключа. Собственные аудиообразцы можно загружать в папку назначенного голоса внутри проекта. Откройте «Аватары/Основной аватар» или создайте ещё одного аватара. Откройте «Описание аватара.md», чтобы описать внешность в редакторе документов. Голос проекта выбирается в папке аватара. Для фотографий предусмотрены папки «Лицо крупным планом», «В полный рост» и «Дополнительные ракурсы». В «Одежде» создайте предмет с уникальным названием и загрузите в него фотографии.

Откройте «Ролики» и выберите проект. Кнопка «Создать ролик» открывает мастер материалов, формата и запуска. На шаге «Материалы» нажмите «Открыть базу знаний». Откройте папку в дереве слева, выделите материалы справа и нажмите «Выбрать». Изначально выбраны промпты, бренд и формулы роликов. При назначении персонажа добавляются папки его аватара и выбранного голоса. [Настройка контекста ролика](docs/decisions/0027-video-context-folders.md). Сохраните черновик для редактирования сценария или нажмите «Собрать видео». Для сборки задайте серверный `POLZA_API_KEY` в локальном `.env`, подключите Codex по инструкции ниже и выполните `docker compose up -d --build backend frontend`. Для запуска без Docker установите FFmpeg и ffprobe в PATH. Каждый клип Veo оплачивается за восемь секунд, число сцен равно длительности ролика в секундах, делённой на восемь с округлением вверх. Мастер показывает результат в плеере и ссылки на исходники в базе знаний. Для ролика с персонажами нажмите «Добавить персонажа», выберите проектный аватар и подтвердите или замените его голос. В брифе обращайтесь к персонажам по именам. Выбранные материалы задают основу ролика. Для раскадровки модель также может посмотреть фото и видео назначенных аватаров в проекте и в личной библиотеке владельца. [Источники раскадровки](docs/decisions/0026-storyboard-avatar-media.md). Для реплик персонажей нужен LUMEAN_API_KEY. FFmpeg накладывает их на клипы Veo. [Отложенная синхронизация губ](docs/decisions/0028-defer-heygen.md). После настройки выполните `docker compose up -d backend`. [Как устроена передача файлов и голосов](docs/decisions/0021-avatar-cast.md). В раскадровке для каждой реплики указаны говорящий, речь в кадре или за кадром и время в исходном клипе. Veo генерирует речь вместе с изображением. Codex получает исходники через MCP и выбирает склейки. В папке ролика доступны задание монтажёру `edit-request.json`, монтажный лист `edit.json` и готовый `final.mp4`. [Передача реплик и исходников](docs/decisions/0020-video-dialogue-and-edit.md). Голос ElevenLabs доступен для отдельной озвучки сценария. Публикация остаётся демонстрационной. [Этапы сборки и хранение](docs/decisions/0018-video-production.md).

На странице проекта в разделе «Сценарии» введите бриф и нажмите «Подготовить сценарий» или выберите время запуска. Статус и текст сохраняются в проекте. По умолчанию подбор материалов, сценарии и тексты для роликов используют Codex CLI с моделью `gpt-6.2-astra` и уровнем рассуждения `high`. Задайте серверный `OPENAI_API_KEY` с доступом к модели или подключите локальный вход ChatGPT. Для второго варианта войдите на компьютере через `codex login`, оставьте ключ пустым и добавьте `COMPOSE_FILE=compose.yaml:compose.codex-login.yaml` в локальный `.env` (macOS/Linux). Все пользователи экземпляра будут расходовать квоту подключённого аккаунта. [Настройки локального входа](docs/decisions/0017-local-codex-login.md). Настройка провайдера в `.env`:

```dotenv
CONTENT_MILL_SCRIPT_PROVIDER=codex
```

| Значение | Команда бэкенда | Серверный ключ |
| --- | --- | --- |
| `codex` | `codex exec` | `OPENAI_API_KEY` |
| `claude` | `claude -p` | `ANTHROPIC_API_KEY` |

Примените выбор командой `docker compose up -d backend` (при первом обновлении образа добавьте `--build`). Обе CLI входят в образ. При прямом запуске Python установите выбранную CLI в PATH серверного процесса и передайте переменные в его окружение. Явно пустая переменная сохраняет прежний режим HTTP API и настройку `CONTENT_MILL_SCRIPT_MODEL`. Переключение действует для новых заданий. Пользователю достаточно аккаунта Content Mill. [Как работает генерация](docs/decisions/0013-managed-scripts.md).

Название можно изменить на странице проекта в разделе «Параметры проекта». Данные клиента редактируются там же в форме контекста.

Перетащите файл с компьютера в папку или нажмите «Загрузить файл». Поддерживаются PNG, JPEG, WebP, MP4, WebM, M4A, MP3, WAV и PDF до 64 МиБ. Окно файла позволяет загрузить новую версию и открыть предыдущие. Браузер обращается к S3 по временной ссылке. При запуске с другого хоста задайте доступный браузеру `S3_PUBLIC_ENDPOINT_URL` и разрешите в CORS хранилища PUT и GET с адреса интерфейса. Для вычисления SHA-256 нужен HTTPS или localhost.

Чтобы использовать документ как источник контекста проекта, откройте его в базе знаний, выберите сохранённую версию и нажмите «Добавить в источники контекста». В том же окне можно убрать связь. При следующем редактировании документа источником останется выбранная версия.

После запуска откройте <http://localhost:3000/register>, укажите имя, почту и пароль длиной от 15 символов. После регистрации откроется главная страница с анимированным маскотом. Из бокового меню доступны проекты и база знаний. Будущие разделы помечены «Ещё не реализовано». Для существующего аккаунта используйте <http://localhost:3000/login>.

Администратор также может создать аккаунт или сбросить пароль в интерактивном терминале:

```bash
docker compose exec backend python -m app.bootstrap_user admin@example.com "Администратор"
```

Команда запросит пароль без вывода на экран. Повторный запуск для той же почты меняет пароль и отзывает её сессии.

## Запуск без Docker

Для бэкенда нужен Python 3.11+:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './backend/src[dev]'
export DATABASE_URL=postgresql://content_mill:content_mill@localhost:5432/content_mill
python -m alembic -c backend/src/alembic.ini upgrade head
python -m uvicorn app.main:app --app-dir backend/src --reload
```

Для запуска без Docker нужны доступный PostgreSQL и S3-совместимое хранилище. Задайте `DATABASE_URL`, `S3_ENDPOINT_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` и `S3_BUCKET`; бакет должен существовать. Локальный фронтенд использует `SESSION_COOKIE_SECURE=false` при HTTP; на HTTPS не задавайте это значение.

Для фронтенда нужен Node.js 22 LTS и npm:

```bash
cd frontend
cp .env.local.example .env.local
npm ci
npm run dev
```

`BACKEND_URL` задаётся только на сервере Next.js и по умолчанию равен `http://localhost:8000`. В Compose он настроен на имя контейнера `backend`.

## Проверки

```bash
python -m ruff check backend/src backend/tests
python -m ruff format --check backend/src backend/tests
python -m pytest -q backend/tests
python -m alembic -c backend/src/alembic.ini check
(cd frontend && npm run lint && npx tsc --noEmit && npm run build)
docker compose config
```

Для команд Python установите зависимости `backend/src[dev]`, активируйте виртуальное окружение и задайте `DATABASE_URL`. Новые тесты бэкенда размещайте в `backend/tests/`. `alembic check` проверяет, что миграции соответствуют ORM-моделям. Для следующего изменения схемы обновите модели, затем выполните `python -m alembic -c backend/src/alembic.ini revision --autogenerate -m "описание"`, проверьте миграцию и примените её. `docker compose config` проверяет конфигурацию без запущенного Docker Engine.

## Автономные демо

Откройте [демо mill](frontend-mvp/index.html) в браузере, сохраняя папку `frontend-mvp/` целиком: стили, скрипты и изображения находятся рядом с HTML. База знаний в нём использует дерево папок, редактирование текстовых файлов и просмотр медиа. Прежний [однофайловый MVP](frontend-mvp/legacy.html) доступен отдельно. Оба интерфейса работают на моковых данных отдельно от FastAPI и Next.js. Подробности — в [README демо](frontend-mvp/README.md).

Первый этап разработки охватывает контекст проекта клиента и создание контента. План интерфейса — в [роадмапе фронтенда](docs/frontend-roadmap.md), серверные границы — в [плане бэкенда](docs/backend-foundation.md), маршруты — в [схеме API](docs/api-schema.md). В Next.js работают вход, проекты, редактор контекста, дерево и текстовые документы базы знаний, две темы. В FastAPI — сессии, проекты, контекст, операции с деревом и версии документов с проверкой владельца и ревизий. Документы и медиа хранятся версиями в S3.

## Структура

```text
backend/
├── src/
│   ├── app/
│   │   ├── domain/       # сущности и ошибки
│   │   ├── application/  # сценарии и контракты по предметным областям
│   │   ├── infrastructure/ # database, providers, storage, video и безопасность
│   │   ├── presentation/ # HTTP (routers, schemas, dependencies, errors) и MCP
│   │   ├── container.py  # сборка зависимостей
│   │   ├── lifespan.py   # запуск и остановка фоновых задач и MCP
│   │   ├── main.py       # единое FastAPI-приложение
│   │   └── bootstrap_user.py
│   ├── migrations/      # версии схемы Alembic
│   ├── alembic.ini
│   ├── Dockerfile
│   └── pyproject.toml
└── tests/
    ├── test_health.py
    ├── test_auth.py
    └── test_projects.py

frontend/
├── src/
│   ├── app/              # страницы, layout и общие стили
│   ├── lib/              # серверный доступ к API и cookie
│   └── proxy.ts          # защита маршрутов и обновление токенов
├── Dockerfile
├── package.json
├── postcss.config.mjs
└── next.config.ts
```

| Путь | Назначение |
| --- | --- |
| `backend/src/app/main.py` | Точка входа Uvicorn `app.main:app`. Маршруты, включая `/health`, подключаются в [HTTP-роутере](backend/src/app/presentation/http/router.py). |
| `backend/src/app/domain/`, `backend/src/app/application/` | Сущности, сценарии и контракты. |
| `backend/src/app/infrastructure/`, `backend/src/app/presentation/` | Реализации PostgreSQL и безопасности, HTTP API. |
| `backend/src/migrations/`, `backend/src/alembic.ini` | Миграции схемы, созданной из ORM-моделей. |
| `backend/src/pyproject.toml`, `backend/src/Dockerfile` | Зависимости Python и контейнер приложения. |
| `backend/tests/` | Тесты бэкенда. |
| `frontend/src/app/` | Маршруты App Router, общий layout и стили Tailwind. |
| `frontend/src/lib/` | Общий код для обращения к API из серверного окружения Next.js. |
| `frontend/src/proxy.ts` | Защита маршрутов и обновление access через refresh. |
| `frontend/package.json`, `frontend/Dockerfile` | Сборка, проверки и контейнер интерфейса. |
| `compose.yaml`, `infra/` | Локальный запуск и место для будущих инфраструктурных конфигураций. |
| `frontend-mvp/` | Автономные HTML-демо на моковых данных. |
| `docs/` | Продуктовая и техническая документация; начните с [карты](docs/README.md). |

Новые функции добавляются в соответствующие слои внутри одного Python-приложения. Перед изменениями прочитайте [AGENTS.md](AGENTS.md).
