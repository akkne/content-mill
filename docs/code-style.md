# Стиль кода Content Mill

Правила применяются к приложениям в `backend/src/` и `frontend/`. Тесты бэкенда размещаются в `backend/tests/`. Отдельное [задание MVP](mvp.md) относится к прежнему однофайловому `frontend-mvp/legacy.html`.

## Общие правила

- Пиши короткий, понятный код без очевидных комментариев, заглушек и неиспользуемых файлов. Файлы адаптеров отключённых AI-моделей сохраняй по [правилу интеграций](architecture.md#интеграции-с-ai-моделями).
- Называй сущности по предметной области: ролик, сценарий, контент-план, бренд, публикация, метрика.
- Добавляй абстракцию при конкретной необходимости: несколько реализаций, граница внешней системы или полезная изоляция в тестах.
- Держи секреты и локальные значения вне кода, в неотслеживаемом `.env`. После появления приложений перечисли нужные переменные в `.env.example`. Публичные переменные Next.js не должны содержать секреты.
- При изменении поведения обновляй документацию и проверяй затронутый сценарий.

## Python

- Следуй PEP 8, используй аннотации типов на публичных границах и форматтер/линтер, выбранный при создании приложения.
- Разделяй файлы по практической ответственности, а не по заранее созданным бизнес-модулям или слоям. Один файл может содержать несколько тесно связанных типов.
- Не смешивай обработку HTTP, правила предметной области и работу с внешними системами в одной длинной функции.
- Для каждой сторонней AI-модели делай отдельный файл адаптера существующего контракта операции. В сценариях вызывай контракт; провайдерские SDK, преобразование форматов и ограничения держи в адаптере и конфигурации выбора модели. При отключении модели убирай её из выбора для новых задач, сохраняя адаптер и [карточку модели](integrations/README.md).
- Обрабатывай ошибки явно; не скрывай исключения без контекста и понятного результата.

## Next.js и Tailwind CSS

- Используй TypeScript для нового интерфейса. Компоненты делай небольшими и называй по назначению.
- Следуй [дизайн-токенам](DESIGN.md) и [дизайн-системе](design-system.md); общие токены перенеси в конфигурацию Tailwind при создании `frontend/`.
- Размещай секреты и серверные вызовы в серверном окружении Next.js. Клиентскому коду передавай только необходимые данные.
- Учитывай доступность: семантическая разметка, подписи полей, управление с клавиатуры, видимый фокус и состояния загрузки/ошибки.
