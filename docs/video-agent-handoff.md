# Передача материалов между этапами создания ролика

Целевой формат v1 для явного выбора персонажей, одежды и индивидуальных голосов. В действующей сборке мастер закрепляет версии выбранных материалов, Codex привязывает референсы к сценам, Nano Banana готовит кадры, Veo создаёт видео с речью, а финальный монтаж использует локальный MCP для доступа к исходникам. [Текущий контракт сборки](decisions/0018-video-production.md).

Реализованный мастер с личной библиотекой, проектными копиями, выбором голоса на роль и синхронизацией губ описан в [решении 0021](decisions/0021-avatar-cast.md). Подтверждение отдельного сгенерированного образа перед запуском остаётся целевым сценарием.

## Что делает пользователь

1. В мастере нажимает «Добавить персонажа». Выбирает аватар из проекта или создаёт его: имя, документ с описанием и хотя бы одно фото лица либо в полный рост. Можно добавить оба и дополнительные ракурсы. Один персонаж может говорить за кадром без подготовки изображения.
2. Для видимого персонажа выбирает одежду на этот ролик: оставить одежду с исходного фото, описать желаемый комплект или выбрать предметы из папки «Одежда» и приложить фото. Несколько фотографий одного комплекта помечаются как общий вид или деталь. Если дан только портрет, а нужна точная длина изделия или посадка в полный рост, мастер запрашивает подходящий референс или предлагает согласовать свободную интерпретацию.
3. Выбирает уже назначенный голос проекта или другой проектный голос для этой роли. Для говорящего нужен доступный voice_id ElevenLabs. Дополнительно можно приложить версию текстового документа с правилами речи и отдельный образец звучания. Для персонажа без реплик голос необязателен.
4. Перед запуском видит список приложений: имя, миниатюра или тип, версия, роль файла, кому он принадлежит в этом ролике. Например, у двух персонажей могут быть разные файлы «Лицо.jpg». Их различают ID версии и привязка к персонажу. Один выбранный образ можно использовать в нескольких сценах.
5. Перед генерацией сцен выбирает или подтверждает подготовленное фото образа. Выбор сохраняется в запуске. Новый комплект одежды создаёт новый образ того же персонажа.

## Пакет агента

В стартовый контекст входят бриф и опись выбранных файлов. Остальную базу знаний текущего проекта агент сможет искать по названию и читать по запросу. Разрешённые имена закрепляются за конкретными версиями в истории запуска. [Решение об инструментах агента и MCP](decisions/0009-agent-file-access.md).

Сервер формирует снимок на запуск. В примере короткие обозначения заменяют реальные ID. Ссылки внутри примера указывают на строки списка файлов. Оригиналы в S3 адресуются через метаданные версий. Входной пакет хранится в истории запуска.

```json
{
  "schema_version": 1,
  "project_id": "project-1",
  "video_id": "video-1",
  "run_id": "run-1",
  "brief": {"goal": "Показать работу фиксатора", "language": "ru", "duration_s": 30, "aspect_ratio": "9:16"},
  "project_context": {"revision": 4, "forbidden_terms": ["лучший в мире"]},
  "files": [
    {"version_id":"product-v2","node_id":"product","name":"Карточка товара.md","version":2,"format":"markdown","role":"product_facts"},
    {"version_id":"desc-v1","node_id":"desc","name":"Описание аватара.md","version":1,"format":"markdown","role":"character_description"},
    {"version_id":"face-v3","node_id":"face","name":"Лицо.jpg","version":3,"format":"image/jpeg","role":"face_reference"},
    {"version_id":"jacket-v1","node_id":"jacket","name":"Куртка.png","version":1,"format":"image/png","role":"outfit_reference"},
    {"version_id":"rules-v2","node_id":"rules","name":"Правила речи.json","version":2,"format":"plain","role":"speech_rules"}
  ],
  "characters": [{
    "character_id": "avatar-7",
    "display_name": "Анна",
    "description_version_id": "desc-v1",
    "face_version_ids": ["face-v3"],
    "full_body_version_ids": [],
    "looks": [{
      "look_id": "look-1",
      "outfit_description": "Куртка застёгнута, воротник открыт",
      "outfit_version_ids": ["jacket-v1"],
      "source_image_version_id": null
    }],
    "voice": {
      "project_voice_id": "voice-node-4",
      "elevenlabs_voice_id": "example-voice-id",
      "model_id": null,
      "voice_settings": {},
      "language": "ru",
      "speech_rules_version_id": "rules-v2",
      "sample_audio_version_id": null
    }
  }]
}
```

В `files` входят все добавленные пользователем версии, включая клипы, музыку, документы и материалы, подтянутые выбранными персонажами. Для остальных материалов можно использовать роли `full_body_reference`, `video_reference`, `music`, `voice_sample` или `attachment`. У одного файла может быть несколько применений: хранить одну строку для версии, привязки указывать в персонаже, образе или сцене. Пустой список означает, что материал не приложен. Для выбранных файлов без распознанной роли агент видит тип и имя и может уточнить назначение.

Список служит описью. Для анализа сервер также передаёт содержимое нужных документов, сами изображения, превью или доступный модели медиаформат. По одному имени файла агент не может заключить, что на фото виден конкретный предмет. Перед каждым вызовом сервер проверяет принадлежность версий проекту и отдаёт адаптеру только входы данного этапа. Способ доставки (байты, временная ссылка или ID загрузки провайдера) выбирает адаптер. Ключи доступа и истекающие URL в снимок не входят.

## Фото персонажа в одежде → изображение или видео сцены

| Этап | Вход | Выход и условие перехода |
| --- | --- | --- |
| Подготовка образа | Описание персонажа, фото лица и/или в полный рост, выбранный комплект и необязательные фото одежды. | Языковая модель по шаблону «Образ персонажа и одежда» составляет задание генератору изображения и перечисляет версии визуальных референсов. Если их недостаточно, возвращает уточнение. |
| Генерация исходного фото | Задание и изображения именно этого персонажа и комплекта. | Адаптер получает изображение, проверяет доступность и формат результата, сохраняет его байты в S3 и регистрирует узел и версию в БД. При сбое этап остаётся незавершённым. |
| Выбор дубля | Новое фото, исходные референсы и описание. | Редактор сверяет лицо, пропорции, цвет и детали одежды, выбирает дубль. Сервер закрепляет **версию подготовленного фото** в поле `source_image_version_id` образа и добавляет её в опись с ролью `character_source_image`. |
| Фото сцены / видео сцены | ID сцены, действие, кадрирование, длительность для видео и точная версия выбранного образа. | Для генерации фото адаптер передаёт подготовленный образ как визуальный референс. Для видео передаёт его как референс или стартовый кадр согласно контракту модели. Если видео строится из отдельного фото сцены, стартовым кадром служит версия этого фото, в истории сохраняется связь с исходным образом. |

Предлагаемое место в дереве — «Ролики / выбранный ролик / Материалы / Изображения / Образы». Технический ключ следует существующему формату `projects/{project_id}/nodes/{node_id}/versions/{id}`. В метаданных дубля сохраняются персонаж, образ, версия промпта, входные версии описания, фото и одежды, модель, попытка и ID файла результата. Персонаж в новом костюме получает отдельный дубль. Прежние сцены продолжают ссылаться на прежнюю версию. Выбранные файлы не перезаписываются.

Пример передачи **после записи фото в S3**. Для сцены с несколькими персонажами у каждого своя запись, поза и положение. Если API модели принимает только один референс, сценарий предлагает сначала создать и согласовать общий кадр.

```json
{
  "stage": "scene_video",
  "run_id": "run-1",
  "scene_id": "scene-2",
  "action": "Анна показывает фиксатор крупным планом",
  "duration_s": 4,
  "characters": [{"character_id":"avatar-7","look_id":"look-1","source_image_version_id":"look-photo-v1","position":"по центру"}],
  "start_frame_version_id": "look-photo-v1",
  "utterance_ids": ["line-2"]
}
```

До выбора нужного изображения зависимые визуальные этапы ожидают. Этапы подготовки текста и закадровой речи могут идти независимо. Изменение голоса затрагивает речь, тайминги и зависимые клипы с синхронизацией губ. Изменение одежды затрагивает образ и сцены, использующие его.

## Голос и дополнительный файл правил

У голоса три разных входа. **Идентификатор ElevenLabs** определяет, кто звучит. **Документ правил** определяет, что персонажу можно говорить и как читать специальные слова. **Аудиообразец** помогает редактору сравнить звучание. Загрузка образца сама по себе не создаёт голос у провайдера.

Предлагаемый формат пользовательского файла «Правила речи.json» приведён ниже. Поля кроме версии необязательны. В интерфейсе те же значения можно будет заполнить формой. Файл является версионированным документом проекта. Если пользователь приложил свободный текст, агент предлагает разнести его по полям и показывает результат для подтверждения.

```json
{
  "schema_version": 1,
  "forbidden_terms": ["дешманский"],
  "preferred_terms": [{"instead_of":"девайс","use":"устройство"}],
  "pronunciations": [{"written":"CM","spoken":"си эм"}],
  "delivery_notes": "Спокойная разговорная речь. Сделать паузу перед пояснением."
}
```

Сценарист учитывает объединение запретных слов проекта и персонажа. Предпочтительная замена применяется, только если итоговая фраза также разрешена и сохраняет смысл. Произношение применяется к озвучке, исходное написание остаётся в субтитрах. Конфликт разрешает редактор до синтеза. Отсутствующий файл правил даёт пустые персональные настройки, проектные правила действуют по-прежнему.

Для реплики сервер хранит внутреннее задание, например:

```json
{
  "utterance_id": "line-2",
  "speaker_character_id": "avatar-7",
  "project_voice_id": "voice-node-4",
  "speech_rules_version_id": "rules-v2",
  "caption_text": "Так работает CM.",
  "spoken_text": "Так работает си эм.",
  "delivery_notes": "Спокойно"
}
```

В снимке голоса можно сохранить выбранные для модели параметры (voice_settings). Если пользователь их не менял, словарь пуст. Пустой model_id означает, что сервер выбирает совместимую модель по конфигурации и фиксирует фактический ID в результате вызова. Поля delivery_notes относятся к редактуре подачи. Перевод в настройки провайдера допускается только при наличии документированного соответствия у выбранной модели.

Адаптер ElevenLabs разрешает voice_id из зафиксированного сервером голоса и отправляет чистый `spoken_text`, выбранную совместимую модель и поддерживаемые параметры синтеза. Пользовательский JSON, список запретов и аудиообразец остаются внутренними входами. Пересылка инструкций как речи приведёт к их произнесению. Обратный результат привязывается к ID реплики, версии аудио в S3 и реальным меткам времени. [TTS ElevenLabs с таймингами](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps).

## Проверка будущей реализации

- Для двух персонажей с одинаковыми именами файлов агент получает все выбранные версии, каждый образ использует свои фотографии и свой голос.
- Персонаж с одним портретом и без фото одежды проходит подготовку образа. Для указанной пользователем точной детали, которой нет ни в описании, ни на фото, агент запрашивает уточнение.
- После удаления временной ссылки провайдера можно заново открыть выбранный дубль из S3 и передать ту же версию в генераторы фото и видео.
- После смены одежды или правил речи старый запуск воспроизводит прежний выбор. При сбое генерации образа фото другого персонажа не подставляется.
- При отсутствии персонального файла правил реплика проходит проектные ограничения. При наличии файла запрещённое слово обнаруживается до TTS, подсказка произношения меняет только звуковую версию реплики.
