# Техническое задание на разработку интерактивного MVP (Single-File HTML)

## 1. Цель и формат поставки
Создать полностью автономный, кликабельный **интерактивный прототип (MVP)** платформы в виде **одного `.html` файла** (`index.html`).
* **Требования к запуску:** Файл должен открываться двойным кликом в любом современном браузере без локального сервера, без сборщиков (Webpack/Vite) и без сторонних локальных файлов.
* **Внешние зависимости:** Допускается только подключение шрифтов Google Fonts и иконок (например, Lucide Icons через CDN или встроенные SVG). Весь CSS и JavaScript находятся внутри `<style>` и `<script>` в одном файле.
* **Контекст моков:** Все данные в прототипе должны быть обезличенными или использовать нейтральный универсальный пример бизнеса (например, *бренд минималистичных термокружек / кофе-аксессуаров «NOMAD CUP»* или *студия умного освещения*), чтобы демонстрация выглядела живой и понятной, но без привязки к каким-либо существующим конкурентам.

## 2. Что должно быть реализовано в MVP (Фронтенд + Моки)

Чтобы человек, которому вы скинете файл, почувствовал продукт как «живой», необходимо реализовать **клиентское состояние (State Management в JS)** и интерактивные симуляции:

### А. Навигация и переключатель языка (`RU` / `EN`) - НЕ ДЕЛАТЬ, только русский
* Мгновенное переключение между всеми **9 экранами** без перезагрузки страницы (SPA-роутинг на Vanilla JS).
* Рабочий переключатель `RU / EN` в шапке (меняет заголовки меню и ключевые подписи интерфейса).

### Б. Интерактивные симуляции (вау-эффект для демо)
1. **Симуляция работы 10 AI-агентов (Экран «Анализ ниши»):**
   * Пользователь нажимает кнопку *«Запустить анализ ниши»* → запускается анимация поочерёдной работы 10 агентов (каждые 350 мс статус меняется с `ЖДЁТ` → `РАБОТАЕТ` → `ГОТОВО`, заполняется прогресс-бар и появляются логи) → через 3.5 секунды плавно открывается экран с результатами анализа, карточками виральных формул и кнопками *«Повторить»*.
2. **Симуляция генерации и монтажа ролика (Экран «Создать ролик»):**
   * Пользователь выбирает формулу (или нажимает *«Повторить»* из анализа ниши) → нажимает *«Сгенерировать ролик»* → запускается экран сборки с прогресс-баром от `0%` до `100%`, пошаговым чек-листом (6 этапов) и живым логом скиллов → открывается экран предпросмотра готового ролика (стилизованный анимированный плеер 9:16 с субтитрами, вкладками *«Публикация»* / *«Сценарий»* и кнопкой *«Опубликовать»*).
   * При нажатии *«Опубликовать»* ролик добавляется в общий список роликов в памяти браузера и появляется плашка с трекинговой ссылкой.
3. **Интерактивный контент-план и Автопилот (Экран «План и автопилот»):**
   * Рабочий тумблер включения Автопилота, выбор количества роликов в неделю (`2`–`7`), кнопки *«Сгенерировать план на неделю»* (заполняет календарь карточками) и *«Очистить план»*.
4. **Живой AI-Маркетолог (Экран «Агент-маркетолог»):**
   * Предустановленный диалог с аналитикой + рабочее поле ввода: пользователь может написать любой вопрос или нажать на быстрые чипсы-подсказки, и агент через 800 мс «напечатает» осмысленный мок-ответ с кнопками перехода к созданию ролика.
5. **Аналитика с переключением периодов:**
   * Переключение пилюль `7 дн` / `14 дн` / `30 дн` динамически пересчитывает цифры в KPI-карточках, воронке и перестраивает высоту столбцов на графике.

## 3. Архитектурный задел под будущий бэкенд и AI-агентов (Backlog для разработки после MVP) - НЕ ДЕЛАТЬ, просто вставить рандомные данные, без интеграции

В коде моков (`MOCK_DATA`) структуру данных нужно сразу заложить так, чтобы потом легко заменить моки на реальные API-эндпоинты и оркестратор агентов:

### 1. Конвейер агентов парсинга (`POST /api/niche/analyze`)
* **Что нужно будет делать агентам на бэкенде:**
  * *Agent 1 (Profiler):* LLM-запрос на извлечение сущностей продукта, болей ЦА и поисковых ключевых слов.
  * *Agent 2–3 (Scout & Scraper):* Интеграция с парсерами соцсетей (Apify / RapidAPI / официальные Graph API) для поиска аккаунтов конкурентов и выгрузки метаданных последних 50–100 постов каждого.
  * *Agent 4–5 (Cleaner & Viral Scorer):* Математический расчёт медианных просмотров аккаунта (`median_views`) и фильтрация видео с коэффициентом `views / median_views >= 2.0`.
  * *Agent 6–8 (Tagger, Vision & Skeptic):* Мультимодальный анализ (транскрибация аудио через Whisper + анализ кадров через Vision LLM) для выделения хука первых 3 секунд, структуры монтажа и отсеивания случайных виральных выбросов.
  * *Agent 9–10 (Formula Builder & Brand Adapter):* Кластеризация похожих сценариев в универсальные формулы и генерация ТЗ под продукт клиента.

### 2. Генератор контента и авто-монтаж (`POST /api/videos/generate`)
* **Что нужно будет делать агентам на бэкенде:**
  * *Scriptwriter Agent:* Генерация сценария по выбранной формуле с инъекцией системного промпта `Brand Voice` (язык, тон, запрещённые слова).
  * *Hook Grader Agent:* Генерация 5 вариантов первой фразы и скоринг каждого от 0 до 100 по критериям удержания.
  * *Media Matcher:* Векторный поиск (Embeddings) по тегам загруженных видеофайлов бренда в медиатеке для подбора подходящих клипов под каждую сцену.
  * *Render Pipeline (FFmpeg / Remotion / Creatomate):* Сборка финального MP4 `1080x1920` — склейка клипов по таймингам бита аудиодорожки, наложение AI-озвучки (ElevenLabs), рендер динамических субтитров и генерация обложки.

### 3. Автопилот и публикация (`Cron / Worker + Graph API`)
* **Что нужно будет делать агентам на бэкенде:**
  * *Planner Agent:* Еженедельная генерация сетки публикаций с контролем баланса рубрик (Доказательство, Обучение, Мнение, История, Оффер) и раскадровки Stories.
  * *Publisher & Tracker:* Генерация уникальной короткой ссылки редиректа (`go.domain.com/r/{video_id}`) перед постингом, публикация через официальные API (Instagram Graph API, TikTok Content Posting API, Telegram Bot API) и связывание вебхуков заявок с конкретным `video_id`.

### 4. AI-Маркетолог (`POST /api/chat/copilot`)
* **Что нужно будет делать агенту на бэкенде:**
  * Реализация Function Calling (Tool Use): выдача LLM доступа к SQL/аналитическим функциям (`get_funnel_stats`, `get_top_converting_formats`, `create_video_draft`) для ответа на вопросы пользователя реальными цифрами из БД.
