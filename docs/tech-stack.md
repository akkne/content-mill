# Технологический стек Content Mill

## Согласовано

| Часть | Технология | Роль |
| --- | --- | --- |
| Серверная часть | Python, FastAPI | Единое монолитное приложение с предметной логикой; сейчас только `/health`. |
| Интерфейс | Next.js, TypeScript | Страницы и серверные возможности интерфейса. |
| Стили | Tailwind CSS | Стили нового приложения с опорой на [дизайн-токены](DESIGN.md). |
| Данные пользователей | PostgreSQL | Аккаунты, проекты, роли, сессии, контекст, дерево папок, версии, связи, статусы и журналы генерации. |
| Файлы и документы | S3-совместимое объектное хранилище | Содержимое всех документов, исходники, изображения, аудио, видео и артефакты генерации. Конкретный провайдер выбирается при реализации. |
| Локальный запуск | Docker, Docker Compose | Контейнеризация и запуск приложений. |
| Демо | HTML, CSS, JavaScript | Автономные [прототипы](../frontend-mvp/README.md); не часть будущего стека приложения. |

Формулировка «бэкенд Next.js» здесь означает серверные возможности веб-приложения, например рендеринг страниц. Основная серверная логика проекта пишется на Python, как зафиксировано в [архитектуре](architecture.md).

## Пока не выбрано

ORM или другой способ доступа к PostgreSQL, очередь задач, провайдер S3, провайдеры AI и соцсетей. Для каркаса используются pytest и Ruff на сервере, ESLint и TypeScript во фронтенде. Не добавляй остальные технологии в обязательный стек до отдельного решения и реализации. Разделение данных между PostgreSQL и S3 описано в [кратком роадмапе](implementation-roadmap.md).

В первом этапе запланированы access и refresh токены. Их формат и способ доставки выбираются перед реализацией; модель сессий описана в [основе бэкенда](backend-foundation.md).
