# Git-процесс Content Mill

Перед изменением индекса или ветки проверь `git status --short --branch`, `git diff` и `git diff --cached`. Сохраняй чужие изменения, включая неотслеживаемые файлы.

## Ветки и коммиты

- Для отдельной задачи используй ветку от актуальной основной ветки, если работа требует коммита. Не переключай ветку, когда это мешает сохранению незавершённых изменений.
- Делай небольшие осмысленные коммиты в формате Conventional Commits: `docs(architecture): describe monolith`, `feat(frontend): add dashboard`.
- Добавляй файлы в индекс явно. Перед коммитом проверь `git diff --cached --check` и полный `git diff --cached`, включая отсутствие секретов.
- Используй настроенные в репозитории `git config user.name` и `git config user.email`. Не добавляй подписи инструмента или `Co-Authored-By`.

## Проверки и публикация

- Запускай проверки, применимые к изменённым файлам. Для документации проверь ссылки, согласованность путей и отсутствие ссылок на чужой проект.
- Для текущих приложений запускай `python -m ruff check backend tests`, `python -m pytest -q tests`, затем в `frontend/` — `npm run lint`, `npx tsc --noEmit` и `npm run build`. Для Compose проверяй `docker compose config`; команды запуска приведены в [README.md](../README.md). Не используй прежние команды `dotnet`.
- После завершения рабочей фичи и успешных проверок всегда пушь ветку в `origin`, если владелец явно не попросил обратного. Отдельное разрешение на push не требуется. Если удалённый адрес или доступ недоступен, сообщи об этом и сохрани локальный коммит.
- Слияние с основной веткой выполняй только по отдельному поручению.
- Не удаляй чужие временные или неотслеживаемые файлы ради «чистого дерева». Перед сдачей сообщи, какие изменения уже были в рабочем дереве.
