# Роадмап фронтенда

> План для `frontend/` на Next.js и Tailwind CSS. Реализованы вход с локальной учётной записью, защищённая стартовая страница, базовая навигация, адаптивная компоновка и переключение тем. Продуктовые данные ещё не подключены. [Автономное демо](../frontend-mvp/index.html) показывает поведение и визуальный язык, но его локальные данные и имитация входа не являются реализацией продукта. Серверные границы — в [основе бэкенда](backend-foundation.md), предлагаемые запросы — в [схеме API](api-schema.md).

Пункт 1 выполнен: общие цвета и состояния находятся в `frontend/src/app/globals.css`, оболочка — в `frontend/src/app/app-shell.tsx`. Next.js принимает пароль только в серверном действии, хранит токены в HttpOnly cookie с `SameSite=Strict`, обновляет access через refresh в `proxy.ts`, загружает текущего пользователя и защищает рабочий маршрут. Выход отзывает сессию на API. Доступен только маршрут «Главная»; будущие разделы обозначены без переходов. Следующая фича — проекты и контекст клиента.

## Первый этап: контекст клиента и создание контента

1. **Каркас и вход — выполнено.** Перенести общие токены, навигацию и состояния из демо в Next.js. Сделать экран входа, загрузку текущего пользователя, защиту маршрутов, обновление access через refresh и выход. Для первого релиза выбран локальный вход с выданной администратором учётной записью. Роли и доступ к проекту проверяет API; фронтенд скрывает недоступные действия только для удобства.
2. **Проекты и контекст.** Список проектов, создание и выбор проекта. Экран базы знаний с деревом папок, хлебными крошками, поиском по названию и тексту, просмотром файлов. Внутри проекта — структурированный контекст клиента: описание, аудитория, продукты, подтверждённые факты, Tone of Voice, ограничения, ссылки на источники. Редактирование показывает сохранение, ошибки и конфликт версий.
3. **Документы и медиа.** Создание папок и текстовых документов, редактирование содержимого и просмотр версий. Загрузка изображений, аудио, видео и других разрешённых файлов через подписанный URL; в списке файл появляется после подтверждения загрузки. Предпросмотр изображения и воспроизведение аудио/видео используют временные URL. Перемещение, переименование и архивирование доступны по разрешениям. Отображаемый путь не служит идентификатором файла.
4. **Создание контента.** Форма задания: цель, формат, длительность для ролика, требования и выбор материалов из контекста проекта. Список черновиков, экран черновика, запуск генерации через API, показ состояния задачи и результата. Просмотр созданного сценария, документов и медиа; история попыток и использованных версий источников. Точные шаги, типы контента и органы управления моделью уточняются после выбора моделей.
5. **Качество сценария.** Доступность с клавиатуры, состояния загрузки и ошибки, пустые экраны, адаптивная раскладка, русский интерфейс; английский язык демо переносится после основных сценариев. Проверить путь «войти → сохранить контекст → загрузить документ → создать контент → открыть результат» на реальном API.
