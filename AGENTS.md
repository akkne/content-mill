# Правила проекта Content Mill

Этот файл — точка входа для работы с репозиторием. Перед изменениями прочитай [README.md](README.md), [карту документации](docs/README.md), [архитектуру](docs/architecture.md), [технологический стек](docs/tech-stack.md), [стиль кода](docs/code-style.md) и [Git-процесс](docs/git-process.md).

## Контекст проекта

Content Mill — платформа для подготовки, планирования, публикации и анализа короткого контента. Возможности описаны в [функциональной спецификации](docs/features-description.md), экраны — в [карте экранов](docs/screens.md). Отдельное задание для прежнего однофайлового демо находится в [MVP](docs/mvp.md).

Сейчас в репозитории есть документация, автономное демо `frontend-mvp/index.html`, прежний однофайловый прототип `frontend-mvp/legacy.html` и запускаемый каркас FastAPI/Next.js. Описание функции в документации не означает, что она уже реализована. Указания `docs/mvp.md` относятся к прежнему прототипу и не задают ограничения будущей платформы.

## Целевая структура

- `backend/` — один серверный монолит на Python/FastAPI. Не делить его на микросервисы или самостоятельные бизнес-модули.
- `frontend/` — приложение Next.js с Tailwind CSS.
- `frontend-mvp/` — автономные HTML-демо.
- `docs/` — продуктовая и техническая документация.
- `tests/` — тесты приложений.
- `compose.yaml`, Dockerfile приложений и `infra/` — локальный запуск и будущие инфраструктурные конфигурации.

Не вводи Kafka, межсервисные API, отдельные БД по функциям или иную инфраструктуру без отдельного решения. Фактическая структура и команды запуска описаны в [README.md](README.md).

## Работа с изменениями

Перед правкой осмотри дерево, `git status --short --branch`, staged и unstaged изменения. Сохраняй чужие изменения. Реализуй только согласованный объём; конкретные контракты взаимодействия, хранилище и внешние интеграции определяются отдельно. После правки проверь ссылки в документации и релевантные проверки из [Git-процесса](docs/git-process.md). Завершённую рабочую фичу пушь, открывай PR в `main` и доводи до слияния самостоятельно после успешных проверок, если владелец явно не попросил обратного. Отдельное разрешение на ревью или слияние не требуется. Команды .NET относятся к другому проекту.
